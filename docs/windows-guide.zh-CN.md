# Windows 使用指南

[English](windows-guide.md) · [首页](../README.zh-CN.md)

## 第一次计算

从工作台的合成街区开始，在左侧修改建筑或 BS / UE。设备须位于建筑之外，且高度不低于地面。先使用较小采样范围和射线数，计算 UE 多径与频响，再运行更大的覆盖网格。真实传播计算需要兼容的 NVIDIA GPU 和驱动。

覆盖视图支持功率和网络 SINR，包含已解析的同频干扰。协作模式是有条件的实验，需要满足相应同步假设。显示设置不改变底层场景；几何或无线参数变化会使旧结果失效。

## 文件和工作区

| 文件 | 用途 |
| --- | --- |
| `.ran.json` | 工作台项目，包含几何、部署和求解设置；结果另行导出。 |
| `.ran-sim.json` | 策略实验，包含场景快照、流程图、参数和资源设置。 |
| `.city.json` | 建模清单，要求 `ran-city-1`、`rf_supported:false`，引用你自己的本地城市资源。 |
| `.geojson` | WGS84 或香港 1980 网格建筑导入；需要检查高度、底面字段和材质假设。 |

软件不附带模型文件。代码生成的合成建筑是功能演示，不是实测城市。GeoJSON 高度字段本身不能证明垂直基准或材质测量。

建模工作区只查看本地资源，不会把精细网格自动转成传播几何。策略工作区首次复制工作台场景；从工作台更新会建立新实验并重置流程图和结果，需要保留旧实验时先保存。存在草稿或运行任务时，按提示选择保存、放弃或取消。

## 策略模式

默认真实信道使用 CUDA 传播。明确标注的合成演示 `reference_fixture` 可用于检查策略闭环，不计算城市场景传播，也不能代替 RF 计算。A/B 对比时应保持资源、种子、场景、移动轨迹和时长一致。

系统模型只覆盖 NR Release 18 的部分功能。解释吞吐量、时延或反馈成本前，请阅读界面的实现范围；链路抽象和参考曲线存在校准边界。

## 语言与自动化

使用原生 **Language / 语言** 菜单。切换时更新已加载页面，不重新载入编辑器；新页面继承所选语言。用户名称和路径保持原样。启动时也可使用 `--language en` 或 `--language zh-CN`。

`Ctrl+S` 保存当前可编辑工作区；建模为只读，请使用页面内的截图功能。工作区切换保留编辑器，不会取消计算。

通过 `RANWorkbench.exe --cli --help` 查看本机控制 CLI，通过 `RANWorkbench.exe --system-cli --help` 查看独立实验 CLI。连接记录包含私密令牌，不要分享或提交。不需要自动化时可加 `--no-automation`。

## 构建与发布

使用干净的 Windows Python 3.12 环境及锁定的 npm 依赖进行构建。保持输出目录完整；软件使用动态库及内置 Qt WebEngine 资源，删除或替换 `_internal` 会影响运行。

`tools/publish_source.py` 按白名单导出不含旧 Git 历史的源码，`tools/verify_public_release.py` 检查 Windows 目录中的私人模型文件类型及必要许可证。压缩包放入 GitHub Releases，不放进 Git 历史。发布前检查源码和二进制两份产物。
